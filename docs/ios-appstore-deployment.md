# SAR Employee — iOS App Store Deployment Guide

Step-by-step guide for shipping the Flutter app `sar_app` to the Apple App
Store. Everything in §2 is already configured in this repo; the remaining
steps happen on a Mac and in App Store Connect.

| Item | Value |

| Bundle ID | `com.sar.employee` (matches Android `applicationId`) |
| Current version | `2.1.4` (build `8`) — from `pubspec.yaml` `version: 2.1.4+8` |
| Minimum iOS | 13.0 (`IPHONEOS_DEPLOYMENT_TARGET`) |

## 2. Already configured in this repo (no action needed)

- **Bundle identifier** `com.sar.employee` in all six build configurations of
  `ios/Runner.xcodeproj/project.pbxproj` (tests use
  `com.sar.employee.RunnerTests`).
- **Permission usage strings** (Arabic) in `ios/Runner/Info.plist`:
  - `NSLocationWhenInUseUsageDescription` — attendance check-in/out GPS
  - `NSCameraUsageDescription`, `NSPhotoLibraryUsageDescription`,
    `NSPhotoLibraryAddUsageDescription` — apartment photo upload
  - `NSMicrophoneUsageDescription` — video capture
- **`ITSAppUsesNonExemptEncryption = false`** — you will NOT be asked export
  compliance questions on every TestFlight build.
- **`LSApplicationQueriesSchemes`** (`https`, `http`, `mailto`, `tel`) for the
  profile screen's `url_launcher` links.
- **App icon** — full `AppIcon.appiconset` including the required
  1024×1024 marketing icon (generated by `flutter_launcher_icons` from
  `assets/icon/app_icon.png`).
- **Launch screen** — `flutter_native_splash` (brand navy `#284A63`).
- **Account deletion in-app** (Profile → حذف الحساب → `DELETE /api/mobile/me`)
  — satisfies App Review Guideline 5.1.1(v), mandatory for apps with login.

## 3. Prerequisites (one time)

1. **Mac** with current **Xcode** (15+; 16 recommended) and command line tools.
2. **Apple Developer Program** membership (USD 99/year) on the company's
   Apple ID — enroll as an **organization** (needs a D-U-N-S number), not an
   individual, since this is a company app.
3. **CocoaPods**: `sudo gem install cocoapods` (or via Homebrew).
   Note: `ios/Podfile` does not exist yet — Flutter generates it on the first
   iOS build; that is normal.
4. Flutter SDK on the Mac, then in the repo: `flutter doctor` must show no
   iOS issues.

## 4. Decide the distribution model (IMPORTANT — read before submitting)

SAR Employee is an **internal employee app** (employee login required, no
public sign-up). Apple's Guideline 3.2 often rejects employee-only apps from
the public App Store. Three options, in recommended order:

1. **Unlisted App Distribution** (recommended): the app goes through normal
   App Store review but is only reachable via a direct link — no search
   listing. Submit the app for review once, and file the unlisted request at
   <https://developer.apple.com/support/unlisted-app-distribution/>
   (do this at first submission; mention it in the Review Notes too).
2. **Public App Store listing**: simplest pipeline, but be prepared for a 3.2
   rejection asking you to move to unlisted/custom distribution.
3. **Apple Business Manager custom app**: private distribution to the
   company's ABM account; requires the company to be enrolled in ABM.

Everything below applies to options 1 and 2 (same build + review pipeline).

## 5. One-time setup in Apple portals

1. **Certificates/App ID**: with automatic signing (next step) Xcode creates
   the distribution certificate and registers the App ID
   `com.sar.employee` for you — no manual work in the developer portal.
2. **App Store Connect → My Apps → ➕ New App**:
   - Platform: iOS
   - Name: `SAR Employee` (must be globally unique on the store; fallback
     e.g. `SAR Employee - سار`)
   - Primary language: **Arabic**
   - Bundle ID: select `com.sar.employee`
   - SKU: `sar-employee-ios` (internal, any unique string)

## 6. Configure signing in Xcode (once per Mac)

```bash
cd sar_app
flutter build ios --config-only   # generates ios/Podfile + runs pod install
open ios/Runner.xcworkspace       # ALWAYS the .xcworkspace, not .xcodeproj
```

In Xcode: select the **Runner** target → **Signing & Capabilities** →
check **Automatically manage signing** → choose the company **Team**.
(The project currently has no `DEVELOPMENT_TEAM` set — this is the one
signing step that must be done by hand; it persists in the project file.)

**iPad caveat:** the project targets iPhone **and** iPad (`1,2`). That means
App Store Connect will also demand 13" iPad screenshots and reviewers will
test on iPad. The app is phone-first — if you don't want to support iPad,
set **Targets → Runner → General → Supported Destinations** to iPhone only
(equivalently `TARGETED_DEVICE_FAMILY = 1` in all three Runner build
configurations) before the first upload. Changing this later is a new
binary, not a listing edit.

## 7. Versioning

`pubspec.yaml` drives both numbers: `version: 2.1.4+8` →
`CFBundleShortVersionString = 2.1.4`, `CFBundleVersion = 8`.

- Every upload to App Store Connect needs a **strictly higher build number**
  (the `+N` part) for the same version.
- Every new store release needs a higher version (the `2.1.4` part).
- Keep iOS and Android releases on the same `pubspec` version — one source of
  truth.

## 8. Build and upload

```bash
flutter clean && flutter pub get
flutter build ipa --release
# Production API is the default (https://sar-iq.com); only pass
# --dart-define=API_BASE_URL=... for non-production builds. Never ship one.
```

Output: `build/ios/ipa/sar_app.ipa`.

Upload with either:

- **Transporter** (free Mac App Store app): sign in with the developer
  Apple ID, drag the `.ipa`, Deliver; **or**
- **Xcode Organizer**: `open build/ios/archive/Runner.xcarchive` →
  Distribute App → App Store Connect → Upload.

Processing in App Store Connect takes ~5–30 min; the build then appears
under **TestFlight**.

## 9. TestFlight (recommended before every release)

1. App Store Connect → TestFlight → the new build (export compliance is
   pre-answered by the plist key).
2. Create an **Internal Testing** group, add team members (up to 100,
   instant, no review).
3. Verify on a real device, minimum pass:
   - login → dashboard loads
   - attendance GPS check-in (location permission prompt shows the Arabic
     string)
   - add apartment with camera + photo-library upload
   - customers: add (Reception role), status change, bulk change, notes
   - inventory browse (تصفّح) with filters
   - profile → privacy/terms links open, logout, delete-account flow
   - RTL layout and Arabic rendering everywhere

## 12. App Review notes (version page → App Review Information)

- **Demo account is mandatory** (login-gated app). Provide a working
  employee account on production, ideally with the Reception role so the
  reviewer can exercise add-customer:
  `demo email / password` — create a dedicated `appreview@...` account and
  keep it active for every future review.
- Notes text (suggested): explain it is an internal app for SAR company
  employees; attendance requires location permission; account deletion is in
  Profile; if pursuing unlisted distribution (§4), state that the unlisted
  request has been filed.
- Phone/email of a reachable contact during review.

## 13. Submit and release

1. Version page → select the TestFlight build → Save → **Add for Review** →
   **Submit to App Review**.
2. Release option: choose **Manually release this version** for the first
   release (you control the go-live moment after approval).
3. Typical review time: 1–2 days. Rejections arrive in Resolution Center —
   a 3.2 (employee app) rejection means switch to the unlisted path (§4.1),
   not a code problem.

## 14. Releasing updates (every subsequent version)

```bash
# 1. bump version in pubspec.yaml, e.g. 2.1.4+8 -> 2.1.5+9
# 2. rebuild and upload
flutter clean && flutter pub get && flutter build ipa --release
# 3. upload via Transporter, wait for processing
# 4. App Store Connect -> ➕ new version -> what's new (Arabic) ->
#    select build -> submit
```

## 15. Troubleshooting

| Symptom | Fix |
|---|---|
| `CocoaPods not installed` / pod errors | `sudo gem install cocoapods`, then `cd ios && pod install --repo-update` |
| `No profiles for 'com.sar.employee'` | Xcode → Runner → Signing & Capabilities → re-tick automatic signing with the team selected |
| Upload rejected: build number already used | bump the `+N` in `pubspec.yaml` and rebuild |
| Missing `ios/Podfile` | expected on fresh clone — `flutter build ios --config-only` generates it |
| Reviewer can't log in | verify the demo account against production `https://sar-iq.com` before every submission |
